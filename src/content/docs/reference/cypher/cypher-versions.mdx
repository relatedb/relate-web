Every :term[Cypher]{id=cypher} statement runs as :term[Cypher 25]{id=cypher-25}, the Neo4j Cypher version aligned with :term[GQL]{id=gql}, the ISO graph query language. relate has one Cypher version: a `CYPHER 25` prefix is accepted and changes nothing, and every other version number fails, `CYPHER 5` included. Syntax that is not settled yet ships as a :term[preview feature]{id=preview-feature} and stays off until `RELATE_PREVIEW` names it.

## Synopsis

```text
[CYPHER 25] [EXPLAIN | PROFILE] <statement>
ALTER DATABASE <namespace> SET DEFAULT LANGUAGE CYPHER 25
RELATE_PREVIEW=<feature>[,<feature> …]
```

`EXPLAIN` or `PROFILE` may also come before the version prefix.

## Version prefix

| Prefix | Result | Notes |
| --- | --- | --- |
| None | The statement runs as Cypher 25 | The default for every statement |
| `CYPHER 25` | The statement runs as Cypher 25 | The prefix changes nothing; a statement that repeats it runs too |
| `CYPHER <n>`, any other whole number | The statement fails | `syntax error: parse error: UnsupportedCypherVersion: <n> is not a valid option for cypher version. Valid options are: 25` |
| `CYPHER 5` | The statement fails with that message, `<n>` being `5` | Up to and including relate 1.0.1, the prefix ran the statement as Cypher 5 |
| A version that is not a whole number, such as `CYPHER 25.0` | The statement fails | `syntax error: parse error: SyntaxError: 22N10 invalid pre-parser option value: "25.0" is not a valid cypher version` |

The CLI exits with [exit code 6](/docs/reference/cli/exit-codes-and-errors#exit-6) on either message. A statement that carried `CYPHER 5` runs once the prefix is removed, unless it relies on Cypher 5 behavior that Cypher 25 changed.

## Default language

Each :term[namespace]{id=namespace} records a default language, which `SHOW DATABASES` reports in the `defaultLanguage` column. The value is for display: no setting changes the version a statement runs as.

| Setting | Value |
| --- | --- |
| Recorded default | `CYPHER 25` for every namespace |
| `ALTER DATABASE <namespace> SET DEFAULT LANGUAGE CYPHER 25` | Runs, and stores `CYPHER 25` |
| `ALTER DATABASE <namespace> SET DEFAULT LANGUAGE CYPHER <n>`, any other whole number, `5` included | `semantic error: UnsupportedCypherVersion: <n> is not a valid option for cypher version. Valid options are: 25` |
| A store where relate 1.0.1 or earlier stored `CYPHER 5` | `SHOW DATABASES` still reports `CYPHER 5`, and statements run as Cypher 25; `SET DEFAULT LANGUAGE CYPHER 25` stores `CYPHER 25` again |
| Effect on statements | None |

## Preview features

`RELATE_PREVIEW` is an environment variable of the process that opens the store. The [Cypher overview](/docs/reference/cypher/overview#preview-features) lists each feature, what it enables and the error it gives while off.

| Rule | Behavior |
| --- | --- |
| Default | No feature enabled |
| When it is read | Once, when the store opens |
| Several features | Comma-separated; spaces around a name are accepted |
| Names | Lowercase, exactly as listed: `Chronological-Comparisons` is unknown |
| An unknown name | The open fails with exit code 1 and lists the known names |
| A feature used while off | Usually `semantic error: SemanticError: preview feature '<name>' is not enabled: set RELATE_PREVIEW=<name>`; the overview lists the exceptions |
| The cells on this site | Run on the WebAssembly build with no preview feature enabled |

## Conformance

The openCypher Technology Compatibility Kit (TCK) is the language contract. relate's published compliance record states that "no engine document publishes a current TCK pass count any more": coverage is measured by a spec harness that reports on each pull request ready for review and never blocks a merge.

The retired in-repository figures are on the [Cypher overview](/docs/reference/cypher/overview#conformance), and [the Cypher dialect](/docs/concepts/cypher-dialect) explains why the pin carried deviations.

## Examples

The cells run in page order on one in-memory store. The default language of each namespace:

```cypher run name=languages
SHOW DATABASES YIELD name, defaultLanguage RETURN name, defaultLanguage
```

String interpolation is a Cypher 25 form:

```cypher run name=prefix-25
CYPHER 25 RETURN s'{1 + 1} hops' AS label
```

`CYPHER 5` is not a version relate runs:

```cypher run name=prefix-5 expect=error
CYPHER 5 RETURN 1 AS one
```

Neither is any other number:

```cypher run name=prefix-4 expect=error
CYPHER 4 RETURN 1 AS one
```

`ALTER DATABASE` accepts `CYPHER 25`, the value every namespace already records:

```cypher run name=set-default
ALTER DATABASE neo4j SET DEFAULT LANGUAGE CYPHER 25;
SHOW DATABASES YIELD name, defaultLanguage WHERE name = 'neo4j'
RETURN name, defaultLanguage
```

It refuses any other version:

```cypher run name=set-default-5 expect=error
ALTER DATABASE neo4j SET DEFAULT LANGUAGE CYPHER 5
```

A preview feature without its opt-in:

```cypher run name=preview-off expect=error
RETURN datetime('2026-01-01T00:00Z') IS BEFORE datetime('2026-06-01T00:00Z') AS earlier
```

The same statement on the CLI, with the opt-in in the command's environment:

```bash verify
RELATE_PREVIEW=chronological-comparisons relate --mode table "RETURN datetime('2026-01-01T00:00Z') IS BEFORE datetime('2026-06-01T00:00Z') AS earlier"
```

```text
+---------+
| earlier |
+---------+
| true    |
+---------+
```

A name that is not a preview feature fails the open:

```bash verify
RELATE_PREVIEW=chronological relate --mode table "RETURN 1 AS one"
```

```text
Failed to open Relate: semantic error: SemanticError: invalid RELATE_PREVIEW value: unknown preview feature 'chronological' (known features: hybrid-search, local-callables, graph-type-opt-props, graph-type-default-values, graph-type-implied-labels, ontology, obfuscated-literals, mixed-label-syntax, float16-coordinate-types, chronological-comparisons, coll-zip, coll-has, cypher-annotations, gql-stddev-aliases, graph-type-show-variants, path-construction, path-concatenation)
```
