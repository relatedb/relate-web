By the end of this page, `relate` is on your `PATH`, checked against the release signing key, and answering a statement. It takes about two minutes. If you're setting up an agent, this page also hands you a prompt it can follow and a block for your repository's `AGENTS.md`.

## Prerequisites

- macOS or Linux on amd64 or arm64, with `curl` and `ssh-keygen` (the OpenSSH client).
- Or Windows 10 or 11 on x64, or Windows 11 on ARM64, with PowerShell and the OpenSSH Client, which Windows includes. [Windows notes](#windows-notes) lists what differs there.
- For a client package: the language's package manager (`pip`, `npm`, `cargo`, Maven or Gradle, `go`, SwiftPM).

## Keep relate up to date

`relate upgrade` downloads the latest release, checks it against the same signing key as `install.sh`, and replaces the running binary. It runs on macOS and Linux; `update` is an alias. On Windows a running `.exe` cannot replace itself, so `relate upgrade` exits with code 1 and names the Windows install command: run that command again to install the latest release over the old one. `relate upgrade --check` works on Windows too.

```bash
relate upgrade --check
```

`--check` reports your version against the latest release and changes nothing. Without it, `relate upgrade` installs the newer release:

```bash
relate upgrade
```

A store written by an older release migrates on its first writable open; [Upgrade a store](/docs/guides/operate/upgrade-a-store) covers the backup to take first.

## Windows notes

The Windows installer on the CLI tab, `install.ps1`, is the Windows counterpart of `install.sh`, which runs on macOS and Linux only. These are the differences from macOS and Linux:

- **Git Bash, MSYS2, and Cygwin.** `install.sh` stops there and prints the line to run instead: `install.sh: on Windows (Git Bash, MSYS2 or Cygwin), install with the PowerShell installer instead: powershell -ExecutionPolicy ByPass -c "irm https://relatedb.ai/install.ps1 | iex"`. That line runs from Git Bash and from `cmd`. The `relate.exe` it installs runs from Git Bash too, in a terminal opened after the install.
- **Windows Subsystem for Linux (WSL).** Use the macOS and Linux tab inside WSL. It installs the Linux binary, which runs in WSL only.
- **ARM64.** There is no native ARM64 build. On Windows 11 on ARM64 the installer installs the x64 build, which runs under emulation, and says so. On Windows 10 on ARM64 it stops with `install.ps1: unsupported architecture: ARM64 before Windows 11 (the amd64 build needs Windows 11 x64 emulation)`.
- **The OpenSSH Client.** The installer checks the release signature with `ssh-keygen`, which Windows has included since Windows 10 version 1809. Without it the installer stops, installs nothing, and names the fix: `Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0`, run from an elevated PowerShell.
- **The C runtime.** As of relate 1.0.2, `relate.exe` carries its own C runtime and needs no redistributable. Releases up to 1.0.1 loaded `VCRUNTIME140.dll` from the Microsoft Visual C++ Redistributable (x64).
- **Downloading in a browser.** The binary has no Authenticode signature, so Windows SmartScreen warns about a copy saved from the [releases page](https://github.com/relatedb/relate/releases). Its check is the SHA-256 in the signed `SHA256SUMS`, which the installer makes.
- **Exit codes and quoting.** In PowerShell the exit code is in `$LASTEXITCODE`, not `$?`. PowerShell also expands `$name` inside double quotes, so put a statement that holds a `$parameter` in single quotes: `relate --param id=1 'MATCH (p:Person {id: $id}) RETURN p'`.
- **Upgrades.** `relate upgrade` exits with code 1 on Windows, with `Error: upgrade: self-upgrade is not supported on Windows (a running .exe cannot replace itself)` and the install command. Run the installer again: it replaces `relate.exe` with the latest release. `relate upgrade --check` reports the installed and latest versions.
- **Extensions.** Extension packages are published for macOS and Linux only. On Windows, `relate extension install` exits with `the extension channel serves macOS and Linux only; this host is windows/x86_64`.

## Verify

Check that the binary runs:

```bash verify
relate --version
```

It prints `Relate v` and the installed version, then the license line.

Then run one statement. A person reads the answer as a table; an agent asks for the :term[envelope]{id=envelope}, the JSON form it parses, and checks the :term[exit code]{id=exit-code}:

::::agentic
:::human[At a terminal]
```bash verify
relate --mode table "RETURN 1 AS ok"
```

```text
+----+
| ok |
+----+
| 1  |
+----+
```

One column, one row. `table` is the default when the output goes to a terminal, so `relate "RETURN 1 AS ok"` prints the same table there.
:::
:::agent[From an agent]
```bash verify
relate --mode envelope "RETURN 1 AS ok"
echo "exit=$?"
```

```text
{"columns":["ok"],"columnTypes":["INTEGER"],"rows":[{"ok":1}],"truncated":false,"notifications":[],"timings":{"elapsed_ms":0.478041,"parse_ms":0.094542,"plan_ms":0.040833,"execute_ms":0.33137500000000003,"lex_parse_ms":0.02225,"rewrite_ms":0.006917,"lower_ms":0.030000000000000002,"result_generation_ms":0.000542},"planCache":"miss"}
exit=0
```

Notice that the envelope lists the columns and their types, and `truncated` says whether rows were cut. Exit code 0 means its rows are the answer.
:::
::::

## What you built

You have a verified `relate` binary on your `PATH`, and it answers both as a table you can read and as the JSON an agent parses. With no `--database`, that statement ran against an in-memory :term[store]{id=store}, which forgets everything when the process exits.
