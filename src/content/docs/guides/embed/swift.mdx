This guide shows you how to use the `Relate` Swift package in an iOS or macOS app: the package dependency, which store to open and how, how Swift values go in as parameters and come back typed, how to group writes and retry a conflict, what a result reports about itself, how to branch on an error, and how to read and write from async code. The package links the engine into your app as a static XCFramework, so there is no server and no network. Every program on this page writes to a store it creates, using the team graph from the [Swift tutorial](/docs/get-started/swift).

## Prerequisites

- A Swift 6 toolchain (Xcode, or the Command Line Tools), building for iOS 16 or later or macOS 13 or later. The programs on this page ran with Apple Swift 6.4.2 on macOS.
- A package or app target to add relate to.

## Add the client

The package is `Relate`, in the repository `github.com/relatedb/relate`. In `Package.swift`, add the dependency and the product:

```swift title="Package.swift"
// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "TeamApp",
    platforms: [.iOS(.v16), .macOS(.v13)],
    dependencies: [
        .package(url: "https://github.com/relatedb/relate", from: "1.2.0"),
    ],
    targets: [
        .executableTarget(
            name: "TeamApp",
            dependencies: [.product(name: "Relate", package: "relate")]
        ),
    ]
)
```

The package compiles in the Swift 6 language mode. Its binary target, `RelateFFI`, is a static XCFramework downloaded from the release the tag names, with slices for iOS devices (arm64), the iOS simulator (arm64 and x86-64) and macOS (arm64 and x86-64); it links `iconv` and `CoreFoundation`. The package ships a privacy manifest declaring no collection and no tracking. [Project](/docs/reference/project#platforms) lists what each release publishes.

## Open a store

`Database(path:)` opens a store for writing and creates it when it is missing; `Database(readOnlyPath:)` loads an existing one once. `Database(url:readOnly:)` does either from a file URL. The path decides the layout:

| Call | Opens | Notes |
| --- | --- | --- |
| `Database.inMemory()` | An in-memory store | The same as `Database(path: ":memory:")`; gone when the database is released |
| `Database(path: "./team")` | A directory store | Created when missing; another process may read it with `readOnlyPath:` while you write |
| `Database(path: "./team.rl")` | A single-file store | Created when missing; opens only while no other process writes it |
| `Database(readOnlyPath: path)` | An existing store, :term[read-only]{id=read-only} | Refuses writes and `checkpoint()`; a missing store is an error, never created |
| `Database(url: url)`, `Database(url: url, readOnly: true)` | The store at a file URL, writable or read-only | A URL that is not a local `file:` URL throws `.invalidParameter` |
| `db.connect(namespace: .system)` | A connection in another namespace | `connect()` uses `.neo4j`; the namespace is a `DatabaseNamespace` |

There is no `close()`. A `Database` closes when its last reference is released, and every `Connection` from `connect()` holds a reference to its database, so a :term[store]{id=store} stays open while any connection lives. This program writes `team.rl`, releases it, and reads it back read-only through a file URL:

```swift run name=open
import Foundation
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

do {
    let db = try Database(path: "./team.rl")
    try db.connect().query(team)
}
print("team.rl exists:", FileManager.default.fileExists(atPath: "team.rl"))

let reader = try Database(url: URL(fileURLWithPath: "team.rl"), readOnly: true)
let conn = try reader.connect()
print("people:", try conn.query("MATCH (p:Person) RETURN count(p) AS people").scalar(as: Int.self))
do {
    try conn.query("CREATE (:Person {name: 'Lin'})")
} catch {
    if let engine = error.engineError {
        print("refused:", engine.gqlStatus, engine.code)
    }
}
```

## Bind parameters and read typed values

A :term[parameter]{id=parameter} goes in as a Swift value, and a column comes back as one. There are three ways to bind:

| Call | Binds |
| --- | --- |
| `conn.query(statement, ["name": name])` | Each entry of a dictionary of Swift values to the `$name` the statement text uses |
| `conn.query(statement, ["name": "Noor", "since": 2024])` | The same, from a dictionary of literals, which are `CypherValue`s |
| `try conn.run("MATCH (p {name: \(name)}) …")` | Each interpolated value of a `Statement` literal, as a generated parameter (`$_p0`, `$_p1`, …) |

Strings, integers, `Double`, `Bool`, optionals (`nil` is `null`), arrays, string-keyed dictionaries, `Foundation.Date`, `URL`, `UUID`, `Data` and the `CypherValue` structs for dates, times, durations, points and vectors all bind. A `[Float]` binds as a list; `CypherValue(vector:)` makes it a vector.

:::warning
Interpolation binds only in a `Statement`, which `run(_:)` takes. `query(_:_:)` takes a `String`, so the same literal passed to `query` is an ordinary Swift string and its values become part of the Cypher text.
:::

A result is a collection of `Record`s. `record.get("since", as: Int.self)` reads a column as a Swift type and throws `RelateError.unexpectedResult` when the column is missing or holds another kind; ask for an `Optional` to accept `null`. `result.decode(Member.self)` reads every record into a `Decodable` type by column name. `record["since"]` returns the `CypherValue` itself.

```swift run name=params
import Foundation
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

struct Member: Decodable {
    let name: String
    let since: Int
}

let conn = try Database.inMemory().connect()
try conn.query(team)

let project = "relate"
let members = try conn.query("""
    MATCH (p:Person)-[w:WORKS_ON]->(:Project {name: $project})
    RETURN p, p.name AS name, w.since AS since ORDER BY since
    """, ["project": project])
for record in members {
    let person = try record.get("p", as: CypherValue.Node.self)
    print(try record.get("name", as: String.self), person.labels, "since", try record.get("since", as: Int.self))
}
print(try members.decode(Member.self).map { "\($0.name) \($0.since)" })

let name = "Noor"
let joined = CypherValue.Date(year: 2025, month: 3, day: 1)
let reviewed = Date(timeIntervalSince1970: 1_767_225_600)
let focus = try CypherValue(vector: [0.25, 0.5, 1] as [Float])
let noor = try conn.run("""
    MATCH (p:Person {name: \(name)})
    SET p.joined = \(joined), p.reviewed = \(reviewed), p.focus = \(focus), p.tags = \(["core", "docs"])
    RETURN p.joined AS joined, p.reviewed AS reviewed, p.focus AS focus, p.tags AS tags, elementId(p) AS id
    """).single()
print("joined", noor["joined"]!, noor["joined"]!.kind)
print("reviewed", noor["reviewed"]!, try noor.get("reviewed", as: Date.self) == reviewed)
print("focus", noor["focus"]!)
print("tags", try noor.get("tags", as: [String].self))

let id = try noor.get("id", as: String.self)
let byId = try conn.query("MATCH (p) WHERE elementId(p) = $id RETURN p.name AS name", ["id": id])
print("by element id:", try byId.scalar(as: String.self))
```

A `Foundation.Date` binds as a UTC `ZONED DATETIME`, to the microsecond, and reads back as the same instant. An element id round-trips through a parameter. A node, relationship or path value is refused as a parameter with `RelateError.invalidParameter`; pass its element id or its properties instead. The [Swift API](/docs/reference/api/swift#values) lists every `CypherValue` case, and [Swift types as values](/docs/reference/api/swift#swift-types-as-values) every conversion.

## Group writes in a transaction

Outside a transaction, each `query` commits on its own. `conn.transaction { tx in … }` runs its body in an explicit :term[transaction]{id=transaction}, commits when the body returns and rolls back, then rethrows, when it throws. The body receives a `Transaction`, which runs statements and nothing else. `begin()`, `commit()` and `rollback()` do the same by hand, and `commit()` returns the :term[bookmark]{id=bookmark}, `"relate:<n>"`, or `nil` when the transaction wrote nothing.

When another connection commits a change to the same node first, the statement or the commit throws an `.engine` error whose `retryable` is true. `conn.transaction(retries: 2) { … }` rolls back and runs the body again on such a failure, up to two more times, so the body must be safe to run more than once. `conn.read { tx in … }` runs its body on one snapshot and always rolls back; a statement that is not a read throws `RelateError.misuse`. This program commits one change by hand, rolls one back, retries a unit of work that loses a conflict on its first attempt, and reads two counts from one snapshot:

```swift run name=transaction
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

struct Abandon: Error {}

let db = try Database.inMemory()
let conn = try db.connect()
let other = try db.connect()
try conn.query(team)

try conn.begin()
try conn.query("""
    MATCH (n:Person {name: 'Noor'}), (t:Project {name: 'opencypher-tck'})
    CREATE (n)-[:WORKS_ON {since: 2025}]->(t)
    """)
try conn.query("MATCH (n:Person {name: 'Noor'}) SET n.role = 'engineer'")
print("committed:", try conn.commit() ?? "nothing")

do {
    try conn.transaction { tx in
        try tx.query("MATCH (a:Person {name: 'Ada'}) DETACH DELETE a")
        throw Abandon()
    }
} catch is Abandon {
    print("rolled back")
}

var attempts = 0
try conn.transaction(retries: 2) { tx in
    attempts += 1
    try tx.query("MATCH (p:Project {name: 'relate'}) SET p.reviews = coalesce(p.reviews, 0) + 1")
    if attempts == 1 {
        try other.query("MATCH (p:Project {name: 'relate'}) SET p.reviews = 10")
    }
}
print("attempts:", attempts)

let (people, reviews) = try conn.read { tx in
    (
        try tx.query("MATCH (p:Person) RETURN count(p)").scalar(as: Int.self),
        try tx.query("MATCH (p:Project {name: 'relate'}) RETURN p.reviews").scalar(as: Int.self)
    )
}
print("people:", people, "reviews:", reviews)
```

Compare bookmarks by their number, never as strings: `"relate:10"` sorts before `"relate:9"`. An auto-commit write carries its bookmark in `result.bookmark`. `conn.runInTransaction(_:retries:)` runs a list of `Statement`s so that all commit or none do. [Transactions and concurrency](/docs/concepts/transactions-and-concurrency) explains what a transaction isolates.

## Read result metadata

A `QueryResult` is a `Sendable` value, copied out of the engine before `query` returns. It is a collection of `Record`s, and beside `columns` and `rows` it carries:

| Property | Value |
| --- | --- |
| `queryType` | `.read` (`"r"`), `.write` (`"w"`), `.readWrite` (`"rw"`) or `.schema` (`"s"`) |
| `namespace` | The namespace the statement ran in, a `DatabaseNamespace`: its `USE` target, else the connection's |
| `bookmark` | An auto-commit write's bookmark, `relate:<n>`; the [Swift API](/docs/reference/api/swift#queryresult) lists when it is `nil` |
| `stats` | The 11 mutation counters, zeros included |
| `notifications` | The planner's notifications, each a `QueryNotification`, filled by `EXPLAIN` and `PROFILE`; empty on a plain run |
| `plan` | The plan document under `EXPLAIN` or `PROFILE`, else `nil` |
| `elapsedMs`, `parseMs`, `planMs`, `executeMs` | The engine's time for the statement and its split by phase, in milliseconds |

The result has no column types.

```swift run name=metadata
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

let conn = try Database.inMemory().connect()

func show(_ conn: Connection, _ label: String, _ statement: String) throws -> QueryResult {
    let r = try conn.query(statement)
    print("\(label): type=\(r.queryType.rawValue) namespace=\(r.namespace) bookmark=\(r.bookmark ?? "nil") columns=\(r.columns)")
    return r
}

let created = try show(conn, "create", team)
print("  nodes", created.stats.nodesCreated, "relationships", created.stats.relationshipsCreated, "properties", created.stats.propertiesSet)
_ = try show(conn, "read", "MATCH (p:Person) RETURN p.name AS name")
_ = try show(conn, "update", "MATCH (p:Person {name: 'Ada'}) SET p.role = 'lead' RETURN p.role AS role")
_ = try show(conn, "index", "CREATE INDEX person_name FOR (p:Person) ON (p.name)")
_ = try show(conn, "routed", "USE system SHOW DATABASES YIELD name RETURN name")

let explained = try show(conn, "explain", "EXPLAIN MATCH (a:Person), (b:Project) RETURN a.name, b.name")
print("plan root:", explained.plan!.root.operator)
for n in explained.notifications {
    print(n.gqlStatus, n.severity, n.title)
    print("remedy:", n.remedy)
}
print("timings within elapsed:", created.parseMs + created.planMs + created.executeMs <= created.elapsedMs)
```

The timings differ on every run, so the program checks only that the phases fit inside `elapsedMs`. [Notifications](/docs/reference/cypher/notifications) lists every notification kind.

## Handle errors

Every error the package throws is a `RelateError`, an enum with five cases. `query`, `run`, `begin`, `commit` and the other calls that can fail only that way declare it as a typed error: in a `do` block that makes only those calls, `error` in the `catch` is a `RelateError` with no cast.

| Case | Thrown when |
| --- | --- |
| `.engine(EngineError)` | The engine or the C boundary refused the call |
| `.invalidParameter(String)` | The package cannot pass a value or a name to the engine: a node, relationship or path value, an integer over `Int64.max`, a latitude off the globe, or a statement, path, namespace, parameter name, map key or datetime zone holding a NUL byte |
| `.unexpectedResult(ResultMismatch)` | A result did not have the shape or type the code asked for: `single()`, `scalar()`, `get(_:as:)` or `decode(_:)` |
| `.misuse(String)` | A call outside the API's contract: a statement that is not a read inside `read`, a `Transaction` used after its body returned, a managed write on a read-only database |
| `.decoding(String)` | A result broke the C contract |

`EngineError` carries `code` (the Neo4j status code), `gqlStatus`, `stage` (`.compile`, `.runtime` or `.internal`), `retryable` and `message`, and four predicates on the code: `isSyntaxError`, `isMissingParameter`, `isConstraintViolation` and `isWriteConflict`. `error.engineError` returns it for the `.engine` case, and `error.isRetryable` is its `retryable`, `false` for every other case:

```swift run name=errors
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

let roleOf = "MATCH (p:Person {name: $name}) RETURN p.role AS role"
let conn = try Database.inMemory().connect()
try conn.query(team)

do {
    try conn.query(roleOf)
} catch {
    if let e = error.engineError {
        print("message:", e.message)
        print("code:", e.code)
        print("gql_status:", e.gqlStatus, "stage:", e.stage, "retryable:", e.retryable)
        print("missing parameter:", e.isMissingParameter)
    }
    print("description:", error)
}

do {
    _ = try conn.query("RETURN 1 AS a, 2 AS b").scalar()
} catch {
    print(error)
}

do {
    _ = try conn.query(roleOf, ["name": "Noor"]).single().get("role", as: Int.self)
} catch RelateError.unexpectedResult(let mismatch) {
    print("path:", mismatch.path, "expected:", mismatch.expected, "found:", mismatch.found)
}

print(try conn.query(roleOf, ["name": "Noor"]).scalar(as: String.self))
```

`String(describing:)` on a `RelateError` gives `Relate: [<code>] <message>` for an engine error. After a `.internal` stage failure the handle may be unusable: `conn.isPoisoned()` probes it, and on `true` you release the connection and open a new one. The [errors reference](/docs/reference/errors#engine-parameter-missing) lists every engine message with its cause and codes.

## Read and write from async code

`try await db.read { tx in … }` and `try await db.write { tx in … }` run a synchronous body off the caller's thread, on connections the database opens and owns: one writer, and up to `Database.Options.maxReaders` readers (2 by default). A `read` body sees one snapshot and keeps nothing. A `write` body is one transaction, committed when it returns and rolled back when it throws, and writes made this way run one at a time. Both take a single `Statement` in place of a body:

```swift run name=async
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

let db = try Database.inMemory()
try await db.write(Statement(team))

let project = "relate"
let names = try await db.read { tx in
    try tx.run("""
        MATCH (p:Person)-[:WORKS_ON]->(:Project {name: \(project)})
        RETURN p.name AS name ORDER BY name
        """).map { try $0.get("name", as: String.self) }
}
print(project, names)

try await db.write { tx in
    try tx.run("MATCH (p:Person {name: \("Noor")}) SET p.role = \("lead")")
}
let role = try await db.read("MATCH (p:Person {name: 'Noor'}) RETURN p.role AS role")
print("Noor:", try role.scalar(as: String.self))

do {
    _ = try await db.read { tx in try tx.query("CREATE (:Person {name: 'Lin'})") }
} catch {
    print(error)
}
```

The managed connections use the `neo4j` namespace. `db.write(retries:tags:_:)` retries a conflict with a writer outside the pool, such as a connection from `connect()`. The [Swift API](/docs/reference/api/swift#managed-asynchronous-access) lists these calls with `checkpointInBackground()`, the commit stream and the live values built on them.

## Own a connection from an actor

When code needs a connection of its own, for `begin()` and `commit()` by hand or for another namespace, keep it in an actor. `Database` is `Sendable`: share one across tasks and actors. `Connection` is not, and the Swift 6 compiler refuses code that shares one between isolation domains, so each connection lives in one actor; open another connection for concurrent work. Calls on a connection are synchronous and block while the engine runs, so make them from a background actor, never the main actor:

```swift run name=actor
import Relate

let team = """
    CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
           (grace:Person {name: 'Grace', role: 'engineer'}),
           (noor:Person {name: 'Noor', role: 'maintainer'}),
           (relate:Project {name: 'relate', language: 'Rust'}),
           (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
           (ada)-[:WORKS_ON {since: 2024}]->(relate),
           (grace)-[:WORKS_ON {since: 2023}]->(relate),
           (grace)-[:WORKS_ON {since: 2022}]->(tck),
           (noor)-[:MAINTAINS]->(relate),
           (ada)-[:KNOWS]->(grace)
    """

actor TeamStore {
    private let conn: Connection

    init(database: Database) throws {
        conn = try database.connect()
    }

    func projects(of name: String) throws -> [String] {
        let result = try conn.query("""
            MATCH (:Person {name: $name})-[:WORKS_ON]->(p:Project)
            RETURN p.name AS project ORDER BY project
            """, ["name": name])
        return try result.map { try $0.get("project", as: String.self) }
    }
}

let db = try Database(path: "./team.rl")
try db.connect().query(team)
let store = try TeamStore(database: db)
async let grace = store.projects(of: "Grace")
async let ada = store.projects(of: "Ada")
print("Grace:", try await grace)
print("Ada:", try await ada)
```

In an iOS app, keep the store in Application Support rather than Documents: `Database.defaultStoreURL(named:)` returns a URL there and creates the directory. To start from a store shipped in the app bundle, `Database.provision(at:from:)` copies it to that URL when nothing is there yet. If the app writes while the device is locked, give the directory `FileProtectionType.completeUntilFirstUserAuthentication`, which `provision` sets on its copy by default. Call `checkpoint()`, or `await db.checkpointInBackground()`, after a bulk load, so the next launch opens from a snapshot instead of replaying the write-ahead log. An app and its extensions that share a store keep it in their App Group container, and only one process holds it writable at a time.

## Verify

Ask the engine which release the app linked:

```swift run name=verify
import Relate

let conn = try Database.inMemory().connect()
let version = try conn.query("CALL dbms.components() YIELD name, versions WHERE name = 'Relate' RETURN versions[0] AS version")
    .scalar(as: String.self)
print("relate", version)
```

A version means the package resolved its binary target, linked the engine, and ran a statement through it.

## If it goes wrong

| Error | Cause | Remedy |
| --- | --- | --- |
| `Relate: [Neo.DatabaseError.General.UnknownError] internal error` from `Database(path:)`, `Database(readOnlyPath:)` or `Database(url:readOnly:)` | Another process or a live `Database` in this one holds the store for writing, or a read-only open named a path with no store | Release the other writer, open a directory store read-only beside its writer, or fix the path |
| `Relate: [Neo.ClientError.Statement.SemanticError] semantic error: WriteOnReadOnlyAccessDatabase: …` (`42N18`) | A write or `checkpoint()` on a database opened read-only | Open with `Database(path:)` for writes |
| `Relate invalid parameter: nodes, relationships and paths cannot be passed as parameters; pass their element id or properties` | A `.node`, `.relationship` or `.path` value in `parameters` | Pass `elementId` or the properties |
| `Relate unexpected result: <column>: expected <type>, found <kind>` | `get(_:as:)`, `scalar(as:)` or `decode(_:)` asked for a type the value does not hold | Ask for the stored type, or for an `Optional` when the value can be `null` |
| `Relate misuse: a <kind> statement ran in a read; nothing it changed is kept — use a write` | A write or schema statement inside `conn.read` or `db.read` | Run it with `transaction` or `db.write` |
| `error: sending 'conn' risks causing data races` (at compile time) | A `Connection` passed to another actor or task is used again where it came from | Keep the connection inside one actor, as in [Own a connection from an actor](#own-a-connection-from-an-actor) |
