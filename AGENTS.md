# relate-web agent contract

The public website for **relate** (formerly *cypherlite*) at `relatedb.ai`: an Astro static site with the docs, the cookbook, the playground, the Pages Functions and a copy of the engine's WASM build. The repositories are public, and since relate 1.0.0 the clients are on PyPI (`relate-db`), npm (`@relate/relate`, `@relate/relate-wasm`) and crates.io (`relate`); the Java jars are release downloads only. What is still open is in [`LAUNCH.md`](LAUNCH.md). Rules here apply to every change. The site's standing contract (tone, invariants, facts and their sources) is [`MAINTAINING.md`](MAINTAINING.md); the documentation plan and style guide are [`DOCS-PLAN.md`](DOCS-PLAN.md) and [`src/content/docs/STYLE.md`](src/content/docs/STYLE.md); each authored content area has its own authoring contract (`src/content/docs/README.md`, `src/content/cookbook/README.md` and `playground/README.md`).

## 1. Rules

### Decision log

A decision about hosting or deploy, build tooling other work depends on, content architecture (sections, URLs, what is authored here versus synced from upstream), agent-facing surfaces (markdown delivery, `llms.txt`, the skill, the MCP server), the design system or any `MAINTAINING.md` invariant, the style guide or glossary rules, or a dependency pinned for a reason gets an ADR in [`docs/adr/`](docs/adr/) **before** or **with** the implementation. Not ADR-worthy: copy edits, a new page in an existing section, bug fixes, dependency bumps with no behaviour change, anything trivially reversible. The full test and the format are in [`docs/adr/README.md`](docs/adr/README.md); `npm run adr:check` enforces them in CI.

- Filename `NNNN-short-kebab-slug.md`; the next number is one more than the highest present; numbers are never reused. One decision per file. Cite others as `ADR-NNNN`, upstream's as `upstream ADR-NNNN`.
- Header lines in order: `# ADR-NNNN: title`, `Status:`, `Date:`. Sections in order: **Context**, **Decision**, **Alternatives considered** (each ending with its rejection reason), **Consequences**; optional **Later references**.
- Status starts `Proposed`; `Accepted` only when the maintainers agree. An accepted ADR is immutable except for **Later references**; a change of mind is a new ADR that names the old one.
- Public record: no ticket, chat or tracker references; no person names (roles, not people); no credentials, internal hosts, or anything `LAUNCH.md` marks internal.
- Line budget: target 80 lines, ceiling 150. Record the why and the shape, not the implementation: no code, config dumps, file inventories or build history.
- Add the record to the index table in `docs/adr/README.md`.

### Documentation

- Docs pages follow `DOCS-PLAN.md` §4 and `src/content/docs/STYLE.md`. Only shipped behaviour, verified against the release binary or the WASM build the site ships. Every Cypher example runs at build and must match its recording; the cookbook has the same rule.
- Docs are data (ADR-0013): twins, skill files and MCP tool results are reference text. Outside a fenced prompt block, do not address the agent in the second-person imperative; never add instructions to a tool result. Every host config block an agent can copy opens the store `--read-only` and pins a version.
- Only substantiated claims on any page; follow the tone contract in `MAINTAINING.md`.

### Upstream

The engine lives in the upstream relate repository. The WASM copy under `public/wasm/`, `install.sh`, `releases.json`, `extensions.json` (+ `.sig`) and the skill bundle `public/skills/relate/` are synced from it, never hand-edited (refresh steps in §4). The docs and the cookbook are authored here and are not synced (ADR-0002). The docs' facts, samples and CLI recordings are pinned to one published relate release (today v1.0.1, upstream `ef436ce`; `_data/engine.json`); re-pin to the next release with `scripts/release-refresh.sh` (§4), never to a moving checkout or a source build. relate restarted its version numbers at 0.1.0 after cypherlite's 0.16.1, so compare releases by publication date, not by number (`releaseNames` in `src/components/docs/install.ts`, the changelog's order).

### Conventions

- The name is `relate` everywhere on the page. Published package names: Python `relate-db`, npm `@relate/relate` (platform packages `@relate/relate-<platform>-<arch>`) and `@relate/relate-wasm`, Rust `relate` on crates.io; Java `com.relate:relate` (release jars, not on Maven Central), Go `github.com/relatedb/relate/clients/go` (no module tag), binaries `relate-<os>-<arch>`.
- Some `cypherlite` strings intentionally remain until upstream artifacts are regenerated (old URLs, release asset names in `releases.json`, `install.sh`). Check `git grep -i cypherlite` before assuming a leftover is a bug.
- Colours come from the tokens in `src/styles/base.css` (`--bg`, `--fg`, `--accent`, `--on-accent`, …), never hard-coded hex. Day is the default theme; Night via `data-theme="dark"` or `prefers-color-scheme`. Code and terminal blocks stay dark in both.
- The site's tooling runs `.ts` directly on Node ≥ 22.18 (type stripping): keep `src/lib/cookbook/` and `src/lib/docs/` to erasable TypeScript (no enums, namespaces or parameter properties) and import with `.ts` extensions. `src/lib/cookbook/result-view.ts`, `cells.ts`, `graph-model.ts`, `palette.ts` and the `schema-*.ts` files are shared with the browser runtime, so keep them free of Node imports.
- The engine is never bundled: the cookbook and docs runtime, and the playground load it from `/wasm/` at runtime. The one NVL module is `src/scripts/cookbook/graph.ts` (pinned 1.2.2; `astro.config.mjs` aliases its Segment telemetry to an empty module).
- The home page (`src/pages/index.astro`) is the Relate home design, one component per section in order: `Hero`, `LoopDemo` (See it work), `Diagram`, `Quickstart`, `Chapters` (Built for agents, Memory with structure, Zero to querying), `Community`, `Cta`, then `Footer play` (the smooth stickers that fall onto the arch, `public/js/footer-play.js`; brand art and icons in `src/lib/home/brand-art.ts`). Examples, Docker, extensions and the reference were removed from the home page: that content lives in the docs and the cookbook. The design export (`tmp/Relate Home.html`) is untracked.

## 2. Layout

### Site shell

- `src/components/Header.astro` is the one top bar (nav links, mobile menu and their JS; ADR-0044); edit nav items there. `src/components/Footer.astro` is the one footer (link columns, the theme switch). `src/styles/base.css` holds the fonts, the Night (default) and Day tokens (the Relate home design's names: `--surface-*`, `--ink`, `--brand`, `--line`, `--term-*`; the older `--bg`/`--fg`/`--accent`/`--code-*` names are aliases of them), the fonts (Geist, Geist Mono and Pixelify Sans under the names Relate Sans/Mono/Pixel; licenses in `public/fonts/LICENSES.md`), the reset and the top-nav styles. `src/layouts/Base.astro` is the shell for section pages; `Placeholder.astro` wraps it for coming-soon pages (never indexed). `src/components/SeoHead.astro` renders the head metadata every page shares (robots, canonical, Open Graph and Twitter cards, icons, alternates, JSON-LD); the layouts pass it props and write no tags. `src/lib/seo.ts` holds the indexing switch (`PUBLIC_INDEXABLE`), the absolute-URL helpers and the JSON-LD builders (ADR-0058).
- Brand assets (source: the "Relate Brand Board" artifact): `public/favicon.svg`, `public/brand/`, the social card `public/og/default.png` (1200×630, one for every page). `favicon.ico`, `favicon-32.png`, `favicon-192.png`, `apple-touch-icon.png`, `icon-512.png` and `icon-maskable-512.png` are rendered from `favicon.svg` by `node scripts/icons.mjs`; `public/manifest.webmanifest` names them. The top-bar logomark is inlined in `Header.astro` and shaded via CSS vars.
- `public/` is copied to `dist/` as-is: `llms.txt`, `install.sh`, `releases.json`, `extensions.json` (+ `.sig`), `.nojekyll`, `CNAME`, `_routes.json`, `_redirects`, `fonts/`, `img/`, `skills/`, `skill.md`, `wasm/` (a copy of upstream `surfaces/relate-wasm/pkg/`: `relate.js`, `relate_bg.wasm`, `opfs.js`, `trap.js`, `snippets/`; it stays in `public/` so Vite never bundles or rewrites it).
- `src/pages/sitemap.xml.ts` generates the sitemap (home, cookbook, every recipe, every docs page, the playground; each with `lastmod`) and `src/pages/robots.txt.ts` generates `robots.txt`; both follow the indexing switch (indexable by default; `PUBLIC_INDEXABLE=false` at build turns it off for a preview). Canonical URLs use `CANONICAL_ORIGIN` (`relatedb.ai`); `NOT_PUBLIC_YET` in `src/lib/cookbook/links.ts` turns pre-launch links into text.
- `MAINTAINING.md` is the standing contract (its "no build step / single page" statements predate the Astro migration; everything else applies). `LAUNCH.md` holds the launch notes, the published names and the launch checks still open. `PLAN.md` and `WEBSITE-PLAN.md` are historical (cypherlite era); do not extend them.

### Cookbook

- `src/content/cookbook/`: one markdown file per recipe; `README.md` there is the authoring contract (its index section is generated). `diagrams/` holds the pre-rendered SVGs (light and dark) and label colours drawn by `scripts/diagrams/render.mjs` (the shared docs and cookbook renderer, an authoring-only package with its own `package.json`: mermaid and puppeteer-core; CI never installs it; every mermaid block needs `accTitle:` and an `accDescr { }` block) in the site's colours, which `src/lib/cookbook/tokens.ts` and `diagram-theme.ts` read from `base.css`; data models are laid out by `src/lib/cookbook/schema-*.ts`. Re-render with `--force` after changing colour tokens. `query-the-relate-docs.md` carries a `docs` data block (a subset of the docs graph with vectors) generated by `scripts/docs-recipe-data.ts`; `codebase-context-graph.md` carries `docs`, `crates` and `chunks` blocks generated from a relate checkout at one commit by `scripts/codebase-recipe-data.ts` (`npm run cookbook:codebase-data -- --src ../relate`; then record the recipe and update the commit and counts its prose and front matter quote).
- `src/lib/cookbook/` is the parser, validator and runner, ported from upstream's Rust `relate-cookbook` harness, plus the page rendering: `site.ts` replays every recipe once per build and fails it on any drift, stale diagram, stale element form or invalid recipe; `render.ts` and `markdown.ts` turn a recipe into HTML. `scripts/cookbook.ts` is the check and record command.
- Interactive elements on recipes (ADR-0046): a `:::<name>{…}` … `:::` block at column 0 is a docs element over the recipe's own steps. `recipe.ts` finds the blocks; `elements.ts` (Node only) turns the recipe into the framework's page (steps as cells, the run as recordings) and shares the docs check and record code, so `cookbook:record` writes each form into `diagrams/<slug>-element-<id>.*` and `cookbook:check` and the build read them back; the page renders the `<docs-element>` host, and the twin carries the static form in place of the directive. Placing an element on a recipe is its directive alone.
- Pages: `src/pages/cookbook/` (the index, `[slug]/index.astro`, and the `[slug]/index.md`, `results.json`, `recipe.json`, `data/<name>.json` and `cookbook/llms.txt` endpoints) on `src/layouts/Cookbook.astro`, styled by `src/styles/cookbook.css`. `recipe.json` is format 1 of the playground hand-off, each cell titled by the heading it sits under (`cellTitles` in `recipe.ts`); each step, the engine bar and the header link `/playground/#recipe=<slug>[&cell=<id>]` via `playgroundHref` in `render.ts`.
- Runtime: pages are complete without JavaScript (every step shows its recorded result). `src/scripts/cookbook/session.ts` makes steps runnable (Run, Edit, Run all, Reset, Stop, parameters, JSON view) on a module worker (`worker.ts`) that loads the engine from `/wasm/`; `src/scripts/cookbook/runtime.ts` starts it on recipe pages (with the docs element loader when the recipe has elements) and `src/scripts/docs/runtime.ts` on docs pages. Graph results open in the NVL view in `graph.ts`, loaded only when one comes into view; `graph-model.ts` and `palette.ts` are shared with the check, which expands the first node of every graph result.

### Docs

- `src/content/docs/`: the pages; `_glossary/` (each term's short and full definition; the first use on a page is a toggletip, `src/lib/docs/glossary-toggletip.ts`, and `/docs/glossary.json` serves them as data); `_data/` facts files (`engine.json`, `cli.json`, `errors.json`, `surfaces.json`, `embeddings.json`, `skill.json`, `usage.json`, `evals.json`, `samples.json`); `_capabilities/`, the capability catalog rendered into the generated section of `concepts/problems-relate-solves` and `/docs/capabilities.json` by `src/lib/docs/capabilities.ts`; `README.md` there is the authoring contract.
- Rendered by `src/lib/docs/` (twins, llms indexes, generated reference pages in `generated/`, checks in `checks/`) and `src/components/docs/`, served by `src/pages/docs/`. Every ```` ```json data=<name> ```` block is also served at `/docs/<page>/data/<name>.json` (its exact text); a twin inlines a block of up to 2 KiB and replaces a larger one with a stub naming that URL, the size, SHA-256 and shape (`src/lib/docs/data-blocks.ts`, `checks/data.ts`, ADR-0049), so every surface built from the twin carries the stub. Generated reference pages (`src/pages/docs/reference/[...page].astro`, which allows more than one path segment): the glossary and the changelog.
- Constructs: the `::::agentic` and `:::deeplink` directives in `src/lib/docs/constructs.ts` (`deeplink.ts` builds and checks host install links); the components in `src/components/docs/`, the sixth being `<Matrix />` (`Matrix.astro` + `matrix.ts`, from `_data/surfaces.json`); the language picker (`LanguagePicker.astro` in the doc header, key vocabulary and `withSpellings` in `src/lib/docs/languages.ts`, script `src/scripts/docs/language-picker.ts`; it shares the `docs-tab` localStorage entry with the tab script in `Docs.astro` and rewrites it after every tab click so each language keeps all its spellings).
- The docs graph: `src/lib/docs/graph.ts` builds it, served as `/docs/graph.cypher`, `/docs/graph.json` and per page `/docs/<id>.graph.md` (capabilities and the problems they solve included). Sections carry a 384-dim `embedding` (vector index `docs_vector`) from the committed `_data/embeddings.json`, written by the authoring-only package `scripts/embeddings/` (transformers.js, its own package.json; CI never installs it) via `scripts/docs-embeddings.ts`; `docs:check` fails on a stale vector (`src/lib/docs/checks/embeddings.ts`). `/docs/docs-artifacts.json` lists every agent artifact with its SHA-256 (signed at launch).
- Sample manifests (ADR-0053): `src/lib/docs/sample-manifests.ts` serves every verified sample as `/docs/<page>/samples/<id>.json` (the program, its recorded output with SHA-256, the client build it last ran on, how the runner runs it) and the index `/docs/samples.json`; the twin's generated `samples` frontmatter lists a page's manifests. The client builds come from `_data/samples.json`, written by hand after a full `docs:samples` replay (commits, toolchain, platform, date, setup's pins; docs:check holds the pins to `scripts/samples/setup.sh`); never infer a client's commit from `engine.json`. `checks/sample-manifests.ts` compares every manifest with its fence and record, and with `--built` with the served page and twin.
- Skills: `public/skills/relate/` is upstream's bundle (synced by `npm run skill:sync`; do not hand-edit). The five task skills (`public/skills/relate-agent-memory/`, `relate-graphrag/`, `relate-schema-design/`, `relate-query-tuning/`, `relate-migrate-from-vector-search/`, each `SKILL.md` + `references/`) are authored here, modelled by `src/lib/docs/skill.ts`, checked by `checkTaskSkills` and `checkTaskSkillCypher` in `src/lib/docs/checks/skill.ts`, and recorded after review in `_data/skill.json` `task_skills`. `public/skill.md` is their entry point; `src/pages/.well-known/` serves the discovery indexes (`agent-skills/index.json`, `skills/index.json`) and every skill's files under `/.well-known/skills/<name>/`.
- The eval harness is `scripts/docs-evals.ts` with `scripts/evals/` (tasks, fixtures, agent wrappers).

### Interactive elements (ADR-0035 to ADR-0042, ADR-0046 to ADR-0048, ADR-0050 to ADR-0052)

- An element is a container directive or a word on a ```` ```cypher run ```` fence. The thirteen directives (`:::plan`, `:::terminal`, `:::schema-live`, `:::vector-explorer`, `:::geo-explorer`, `:::mcp-tryout`, `:::agent-trace`, `:::docs-graph`, `:::storage-animator`, `:::scale-demo`, `:::graph-diff`, `:::timeline`, `:::embed-question`) each have a build side `src/lib/docs/elements/<name>.ts` (its static form recorded by `docs:record` into the page's `diagrams/`, hash-stamped on its inputs and its words), a lazy browser module and styles in `src/scripts/docs/elements/`, and a case file `scripts/browser-cases/<name>.ts`. The two cell words (graph view extras, module `graph-extras`, and `timing`) have no build side (the cell's recording is their static form), only the browser module, styles and case file, with shared helpers in `src/lib/docs/elements/_<name>-*.ts`. All are found by directory (docs README "Interactive elements"). A cookbook recipe takes any directive too (ADR-0046, Cookbook above): the same build file, module and case file, its form recorded by `cookbook:record`; cookbook:browser runs each case file on the first docs page and the first recipe that carry the element.
- Every status line opens with the shared wording and prints durations with the one formatter in `src/lib/docs/elements/_wording.ts` (`recordedLine`, `liveLine`, `formatMs`: one decimal, the step of the browser's timer). NVL stays in `graph.ts` (`renderGraph`, `renderNetwork`). An element whose graph must not touch the page's database opens its own with `page.scratch()` (a second engine worker, closed to hand its memory back); one that reruns a recipe step reads its parameters with `CellHandle.runParams()`, which fetches a dataset where `params()` reads only an editable block. `:::embed-question` (ADR-0050) is the one element that fetches from a third party: after a button press, a worker of its own fetches bge-small-en-v1.5's weights and tokenizer from the Hugging Face hub at the pinned revision and checks them against the SHA-256 pins in `src/lib/docs/elements/_embed-question-model.ts`; its runtime (`onnxruntime-web`, `@huggingface/tokenizers`, pinned exactly in package.json) is bundled into that worker's lazy chunk, never with the page, and `reference/privacy-and-telemetry` names the request.
- `src/components/docs/PageRuntime.astro` loads the page runtime only on pages with cells or elements. A docs or recipe page runs under 60 KB of its own JavaScript before lazy chunks: `docs:check -- --built` measures it, and `cookbook:browser` fails a page that loads more, or a script the count misses.

### Playground

`playground/` is the full-screen SPA served at `/playground/` (moved from upstream `examples/wasm-playground/`). Its **own package** (Vite 5, React 19, TS 5, Neo4j Needle, NVL, CodeMirror) with its own lockfile and build tuning in `vite.config.ts`; the root `tsconfig.json` excludes it. Install with `npm ci --prefix playground`. Its worker loads `/wasm/relate.js` at runtime (types from `public/wasm/relate.d.ts`), and the `site-wasm` plugin serves `public/wasm/` to its dev server. The cookbook hand-off (`#recipe=<slug>[&cell=<id>]`) imports `src/lib/cookbook/cells.ts`. See `playground/README.md`.

### Pages Functions

`functions/` holds the Cloudflare Pages Functions, compiled by `wrangler pages deploy dist` from the repo root. `functions/docs/_middleware.ts` does the docs content negotiation (`Accept: text/markdown` → the twin; `?section=<anchor>` → one section) using `src/lib/docs/negotiation.ts`; `functions/_middleware.ts` logs fetches of the twins, the data files they link, `llms.txt` and the skill; `public/_routes.json` limits the paths that invoke a function. Keep no `package.json` or `node_modules` in `functions/`: wrangler runs esbuild on every file under it. GitHub Pages, the interim host, does not run it; everything else on the site is static and works there.

## 4. Refreshing from upstream

The site tracks published releases. `engine-release.yml` runs `scripts/release-refresh.sh` on upstream's `relate-release` dispatch and opens a draft pull request; the same script runs on a laptop with `gh` signed in, against a clone of upstream at the tag (never the working checkout):

```bash
git clone --branch vX.Y.Z --depth 1 <upstream relate repository> <scratch>/relate-vX.Y.Z
bash scripts/release-refresh.sh --version X.Y.Z --upstream <scratch>/relate-vX.Y.Z --report <scratch>/report.md
```

It syncs `install.sh`, `releases.json` and `extensions.json` (+ `.sig`) (signed or generated upstream; the deploys also fetch them with `scripts/fetch-discovery.sh`; never hand-edit them; `runbooks/release-discovery.md`), installs the release binary through `install.sh`, copies `public/wasm/` from the release's `@relate/relate-wasm` asset, bumps `_data/engine.json`, runs `skill:sync`, `docs:cli-check -- --record`, `cookbook:record` and `docs:check -- --record`, and reports each step. What it leaves to a person, in order:

- Every page step the CLI replay flags: the page's text fence is authored, so fix the command or the prose and replay (`RELATE_BIN=<the installed binary> npm run docs:cli-check -- --record`). Timing values never drift (ADR-0054); a changed shape, message or count does.
- `node src/lib/docs/elements/_terminal-facts.ts --write` and `RELATE_BIN=<binary> node src/lib/docs/elements/_terminal-record.ts`, then `docs:check -- --record` again for the element static forms.
- The language samples: `bash scripts/samples/setup.sh --upstream <the clone> --out <scratch dir>` (Python, Node.js and Rust from their registries at the release, the rest from the clone; ADR-0062), `source <out>/env.sh`, `npm run docs:samples -- --record --require`, then rewrite `_data/samples.json` by hand with the commit and toolchains the replay ran on.
- The changelog entry in `_data/changelog.json` (newest first by publication date), version strings in prose and in transcripts that are not replayed (server replies, the shell, `relate upgrade`), the task skills' `version` and the claims they make, then `npm run skills:record` after a build.
- `npm ci --prefix scripts/embeddings && npm run docs:embeddings` for the sections whose text changed, `COOKBOOK_ONLY=query-the-relate-docs npm run cookbook:record`, and `node src/lib/docs/capabilities.ts --write`.
- `npm run ci` for the whole required check.

## 5. CI and deploys

Operating and debugging: `runbooks/` (start at `runbooks/README.md`: the site is wrong or down, a deploy failed, rollback, DNS and hosts, the WASM demo, release discovery).

- `cookbook.yml` runs on every pull request and push to `main` (no paths filter, so it can be a required check) as parallel jobs (ADR-0061): `source` (cookbook and docs unit tests, `adr:check`, `docs:check`, `docs:lint`, `cookbook:check`, `astro check`) beside `build` (`check:playground`, build, `dist/` uploaded; the playground's packages and build cached), then `built` (`docs:check -- --built`) and four `browser` shards (`cookbook:browser` with `BROWSER_SHARD=<k>/4`); the last job, `check`, passes only when all of them did and is the status to require. A browser check must not rely on another having run first in the same Chrome profile: another shard may run it. CI runs Node 24; regenerate a lockfile with the npm that ships with it when `npm ci` refuses one.
- Not required, on a paths filter (`install.ts`, its script, the workflow), weekly and by hand, needing no secret: `docs-windows-install.yml` (pastes the install page's Windows PowerShell block on `windows-latest` in Windows PowerShell 5.1 and PowerShell 7; a copy with another signing key must install nothing, the block must install `relate.exe` on `PATH`, and a second paste must replace it; ADR-0064).
- Not required because of its paths filter (`functions`, its check script, the docs sources and pages, `src/layouts`, the skill and `llms.txt`, `_routes.json`, the root package files), and needing no secret: `docs-negotiation.yml` (build, `docs:negotiation-check`).
- Not required, and needing a binary, clients or a token: `docs-cli-check.yml` (weekly, by hand, and on pushes to main that touch the docs, `public/wasm` or the check; it installs the latest release with `RELATE_UPSTREAM_TOKEN` and fails on any drift, timing values masked per ADR-0054) and `docs-samples.yml` (weekly and by hand, from the tag `_data/engine.json` names) and `engine-release.yml` (on a `cli` `relate-release` dispatch; opens a reviewed docs refresh pull request that does not gate the discovery files). Not required, spending the operator's model account: `docs-evals.yml` (by hand, or on a `relate-release` dispatch once the repository variables `DOCS_EVALS_AGENT_PACKAGE` and `DOCS_EVALS_HARNESS` are set; the agent job has read-only permission and no stored credential, and a second job opens the scores pull request).
- Deploys: `deploy-pages.yml` (GitHub Pages, the interim host) and `deploy-cf.yml` (Cloudflare Pages, needs secrets) both run `npm ci`, `npm ci --prefix playground`, `npm run cookbook:check` and `npm run build`, and publish `dist/` (on Cloudflare, with the Pages Function in `functions/`). `deploy-cf.yml` also runs `docs:negotiation-check` before `pages deploy` (wrangler pinned to 4.158.0 by `WRANGLER_VERSION`, which both read), and splits into a `build` job with no Cloudflare secret and a `deploy` job that alone reads the token, installs with `--ignore-scripts` and runs no build, then, on pull requests, a `comment` job with no secret posts the preview URLs on the pull request and edits that comment on later pushes (ADR-0059). Only same-repository branches get previews; never move it to `pull_request_target`.
